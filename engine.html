        == is overridden to build an Equation. What the class stores is

notes

      

        Drag the dividers to resize the panes; double-click one to put it back. Tick
        auto-run and the laws re-evaluate when you stop typing, and the page boots Ruby
        by itself next time. Both settings are remembered between visits.
      

      

        Anything you change is marked the way an editor marks it: a bar in the gutter beside every
        line you touched — green for new, blue for altered — a red wedge where lines were taken
        out, a dot on the tab and an M in the tree. Revert edits puts
        this repository's own text back.
      

      

        The console under the code is a real irb against the same VM. Locals persist between lines, and anything you redefine in the
        editor is live there the moment you re-run.
      

      

        Solving knows nothing about which side of the equals sign anything was on. It finds the
        equation that mentions the unknown and nothing else unknown, then finds a root of
        left − right — Newton first, bisection when Newton wanders off the branch the
        quantity declared. Those two live in solver.rb and know nothing about physics
        at all; they are handed a lambda and a range.
      

      

        Nothing was rearranged to solve backwards. a is not sqrt(c² − b²)
        anywhere in the source — the same stored equation is handed to a root finder with a
        different unknown.
      

      

        As it was written means it. A Var carries two names: the quantity it
        is looked up by, and the notation you typed — so { c ** 2 == a ** 2 + b ** 2 }
        prints back as itself rather than as
        hypotenuse ** 2 == leg_a ** 2 + leg_b ** 2. Solving still goes by the
        quantity, which is what lets two laws written in different letters agree about the same
        thing.
      

      

        Re-running starts from where the first run started. Ruby will reopen a module that is no
        longer in the file, so everything these files defined is taken away before the next run
        defines it again — and nothing is taken away until every file parses, which is why a
        half-typed law leaves the working one standing rather than half-replacing it.
      

      

        The panel above was not written; it was generated. notation.rb walks the same
        tree the solver walks and emits MathML instead of a root, so a law states itself — its
        quantities, what each is written as, the branch it lives on, and every equation typeset.
        Edit pythagoras.rb and it restates itself. Nothing is loaded to draw it:
        browsers render MathML natively.
      

      

        Two vocabularies meet in this chapter, and the names say which is which.
        expression.rb, equation.rb and solver.rb are
        algebra: they hold variables and know no physics at all — grep them for the word
        and you get nothing. quantities.rb, law.rb and
        scenario.rb are physics: they hold quantities. The seam is one line
        in scenario.rb, where a quantity is looked up and then an equation is asked
        which variables it involves.
      

      

        within: earns its keep even here. Squaring loses the sign, so the residual for
        a has a root at −3 as well as 3, and bisection scanning from the bottom would
        find the negative one first.
